## Timing choices

For a fully live timeout, prepare a separate GB-ORG-00 synthetic listing at the start of the slot or before the timed run, note when it was started and let its three real 30-second waits run while demonstrating other steps. Show elapsed history honestly; do not claim it started during the certification explanation if it started earlier. Do not edit assessed timer durations to fit the slot. Alternatively, use the completed version-11 timeout records from the live register.

If fewer than twelve minutes are available, agree which paths are shown live and which are explained through evidence. Keep the connected F1-to-F2 journey, traceability and individual understanding visible; do not rush all exception branches into a single run.

## Failure recovery during rehearsal

| Symptom | Demonstrator response |
| --- | --- |
| Paused/resuming environment | Show status, resume if permitted and wait for Healthy; explain worker reconnection. Do not report disconnected workers as a completed business exception |
| Request certification verification stays active | Check certification-worker acknowledgement and permissions; this is different from GB-ORG-00 waiting at the result gateway |
| Publish product listing stays active | Check the shared catalogue worker and configured database; preserve the same instance while recovering |
| Product absent from F2 dropdown | Confirm F1 persisted it; start a new F2 update to obtain a fresh catalogue snapshot |
| Message API returns success | Show the corresponding instance/end state and database change; publication acceptance alone is insufficient |
| Insufficient stock | Explain the preserved stock and incident limitation; do not call it an out-of-stock notification or a refund |
