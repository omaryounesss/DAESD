# F2 operational-to-executable mapping - current version

Version 2 was deployed on 24 November 2026 with both BPMNs and all three forms. The shared worker and separate local Notification Service were started by Omar. Native Tasklist submission, correction, administrator allowance, seasonal messages and zero-stock handling were exercised; see [live evidence](f2-tasklist-live-validation-2026-11-24.md).

The separate Modeler review project is [f2-tasklist-executable](https://hub.camunda.io/workspaces/92fa97e5-a7b4-4f61-8f95-8e16edc03f4c/projects/31fc8f52-d77b-47f0-8ffa-e7f9f93349bb). Its draft was updated and visually checked on 24 November. The extra Tasklist lane was removed, the mixed interaction lane is Marketplace operations, and the obsolete Producer-to-correction message connector was removed. End-date documentation now states the inclusive UTC boundary. Subsequent manual layout adjustments in Modeler do not change runtime behaviour; do not redeploy old fixed-date drafts.

| Operational behaviour | Executable refinement |
| --- | --- |
| Producer sends stock/season details | Additional none start, catalogue-loading service task and native producer submission form feeding the original validation merge |
| Corrected stock update received | Same ID and business flow endpoints, refined into native producer correction task with errors and prior values |
| Administrator reviews repeated failures | Existing task/form retained, with deployment form binding and PT48H boundary timeout |
| Seasonal timer starts | Same seasonal business routes, triggered by per-product scheduler messages rather than fixed deployment dates |
| Notification Service participant | Existing send jobs now queue delivery to a separate HTTP simulation with its own durable receipts |
| Paid order reduces stock | Existing message name, business route and service jobs retained |
| Original diagram | Operational sources unchanged; executable lanes/layout explicitly refined. External labels move with their shapes; correction edges are orthogonal and leave the task boundary |

Three forms are linked: submission, correction, administrator review. Users claim tasks through Tasklist; a lane name does not implement producer authentication or product ownership. The shared catalogue dropdown is a classroom demonstration interface.

On 25 November the producer update/correction forms were exported with native date pickers. Their newly generated keys were corrected to availableFrom/availableUntil and the exports are now preserved in source/forms. See the [date-picker compatibility review](f2-date-form-review-2026-11-25.md) for the four key changes, local checks and pending live redeployment check.

Submission outputs only productId, quantity and dates. Correction outputs only quantity and dates. updateId is generated by the worker; correction counter and validation flags are not editable producer fields. The initial form uses a catalogue snapshot; existence and business values are rechecked before persistence.

Seasonal messages include productId, seasonVersion, boundary and due date. The durable scheduler queues them; the matching Camunda worker job applies availability and completes the schedule. Changed dates cancel old pending/queued schedules, and in-flight stale messages are checked again. Inclusive end dates use UTC midnight on the following day. See [scheduler details](f2-season-scheduler.md).

Notification jobs durably queue events in the same transaction as their business record. The dispatcher retries delivery outside that transaction; the receiver deduplicates stable event IDs. BPMN completion and service acceptance are distinct evidence. Email/SMS is intentionally not implemented.

Legacy correction messages only apply to version-1 waiting instances. New instances use forms. Old instances are not automatically migrated. The original operational-model author must review these execution refinements for consistency. AI assisted executable implementation, code, forms, tests and mapping; the group must disclose it accurately and understand the logic.
